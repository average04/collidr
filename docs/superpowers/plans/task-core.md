# Scheduler and state brief

Implement `src/runner/state.ts`, `scheduler.ts`, `prompt.ts` and `test/runner-state.test.ts`, `runner-scheduler.test.ts`. Own these files only. Read design and types.ts. Test first with real SQLite and fake AgentAdapter functions; no model calls. No commits.

Export `RunnerState` constructed with hub database file string. Sidecar `${database}.runner.db`, own schema (never alter hub tables). Public API root CLI needs:
- `acquire(workspace: string, owner: string, pid?: number): boolean`; `heartbeat(workspace,owner): void`; `release(workspace,owner): void`; `requestStop(workspace): void`; `shouldStop(workspace,owner): boolean`; `status(workspace): unknown` JSON serializable.
- `enqueue(workspace: string, agentId: string, prompt: string): string`; `retry(workspace:string, agentId:string): void`; `close():void`.
- Additional internal methods you need are yours to design. Persist per-agent sessionId, cursor, blocked reason, output and active work; queued tasks; per-thread invocation counts. Don't trust PID alone to clear a live lease. Heartbeats expire after 15 seconds but don't steal if owner PID still alive. On dead supervisor acquire, mark interrupted jobs blocked; if recorded child PID alive refuse takeover until it exits, preventing overlaps. Parent start failure won't require a user retry if no task began.

Export `RunnerScheduler` constructor `(config:RunnerConfig, store:Store, state:RunnerState, adapters:Record<Provider,AgentAdapter>, options?:{log?:(message:string)=>void})`. Root acquires/releases lease separately and heartbeats via interval. `tick(signal?:AbortSignal): Promise<boolean>` handles at most one actionable run and returns true if one ran, false if idle. Root owns poll loop/stop checks; tick abort signal bounds adapter turn with config.turnTimeoutMs. Public `workspace` string matches canonical config.workspace and `workspaceId` resolves from Store. Register agents in constructor. Additional internal APIs okay.

Serialize one run per workspace, round robin agents; blocked agents don't relaunch automatically. Keep delivery cursor independent of Collidr ack. Process visible events in sequence, preserve interleaved thread work (don't skip second thread). Only wake for open current requests directed to participant, incoming messages on open threads, verdict/request completion to author. Lifecycle-only, own, closed/stale events advance without model. If event batch reaches limit continue next tick. An agent successful run must show meaningful Collidr progress by that actor in target workspace/thread, else blocked and cursor retained. Queued task also requires progress/new Collidr thread, so a silent final answer doesn't lose a handoff. New arrivals during invocation remain pending. Do not consume later interleaved events. Exhausted per-thread budget blocks. Persist sessions immediately from onSession and child PID from onSpawn. On failures/permission/timeout retain checkpoint, mark work blocked until retry.

Prompts identify agent/workspace and peers, trusted task vs untrusted thread content; instruct explicit Collidr read, respond to current request, author resolves after approvals, return promptly rather than wait loops, no authority to autoapprove tools/merge. Include IDs rather than blindly embedding event bodies. Tests: task -> author requests review -> reviewer approval -> author resolves (three automatic invocations), duplicate owner, restart, interleaved threads, closed/stale, no progress, abort/timeout, failure no retries, max budget. Core APIs can be refined by messaging root.
