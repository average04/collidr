# Releasing Collidr

The initial `collidr@0.1.0` package is unpublished. Registry installation becomes available only after the deliberate publication step below. Do not treat a successful local tarball test as registry availability.

1. Use a current Node 22 (22.12+) or 24 release. Start from a clean reviewed checkout and stop any existing runner before upgrading its installed package.
2. Keep `package.json`, the root metadata in `package-lock.json`, and `src/version.ts` at the same release version. Preserve dependency resolutions unless intentionally upgrading them.
3. Run `npm ci`, `npm run typecheck`, `npm test -- --no-file-parallelism`, and `npm run test:package` sequentially. Check the OS/Node CI matrix. The artifact smoke stages clean source, builds during `prepack`, installs a tarball into an isolated prefix without devDependencies, and checks installed setup, doctor and MCP. It uses fake providers and isolated databases.
4. Use the exact smoke-tested tarball retained at `artifacts/collidr-0.1.0.tgz` and its printed SHA256. Inspect the contents: compiled `dist`, README, LICENSE and package metadata only. No source, tests, secrets or local bookkeeping. Keep the tarball and its SHA256 with the release evidence. `npm run pack:release -- --json` is useful for source sharing, but any repacked or changed artifact must be tested again before publication. There is no consumer install-time TypeScript build. The `pack:release` command enables the pack hook explicitly while preserving the repository `.npmrc` policy of disabling dependency install scripts.
5. On a clean machine, install the tarball with `npm install --global ./collidr-0.1.0.tgz`, use already installed/authenticated providers, run `collidr doctor` and `collidr setup` in a test project, and check the printed runner commands. A deliberate live model test is separate from packaging verification. Preserve the configuration and install location across upgrades; stop, upgrade, start with the same config.
6. Confirm npm account ownership/name availability and package access. Run `npm login` if needed, then `npm whoami`. Review the exact tarball, version, metadata and account before deliberately running `npm publish ./artifacts/collidr-0.1.0.tgz --access public`. Publication is a manual final decision; there is no publish workflow. Do not claim the registry route works before publication succeeds.
7. Verify registry metadata and a clean-machine registry installation after publication, then announce the version and artifact checksum.
